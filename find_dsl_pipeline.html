0. Program being transformed

This is the exact source program used in the walkthrough:

(find "ROOT"
  (or
    (and (name "skip") (prune))
    (type "f")))

For the evaluation trace, ROOT contains:

ROOT/
├── a.c
├── b.txt
├── skip/
│   └── hidden.c
└── sub/
    └── c.c

2. ADT grammar

Program ::= (find ROOT Expr)
Expr    ::= (name GLOB)
          | (iname GLOB)
          | (path GLOB)
          | (type f | d | l)
          | (size [+|-]BYTESc)
          | (empty) | (prune)
          | (not Expr)
          | (and Expr Expr)
          | (or Expr Expr)

The compiler maps these forms to a recursive ADT:

Name(pattern, insensitive)
Path(pattern)
Kind(file | directory | symlink)
Size(operator, bytes) | Empty | Prune
And(left, right) | Or(left, right) | Not(child)

3. Step-by-step evaluation

Step 1 — tokenize and parse

The source program is parsed as a parenthesized tree. The root is find, the filesystem root is ROOT, and the expression is an or.

find root = "ROOT"
expression = Or(
  And(Name("skip"), Prune),
  Kind('f')
)

Step 2 — construct the ADT

Or(
  And(
    Name { pattern = "skip", insensitive = false },
    Prune
  ),
  Kind { value = 'f' }
)

This is the program representation passed to the compiler’s type stage.

Step 3 — quote the ADT

Code { syntax =
  Or(And(Name("skip"), Prune), Kind('f'))
}

Quotation makes the ADT explicit code data. It is not executed merely because it has been constructed.

Step 4 — normalize and check

normalize_code(Code { syntax = Q })
→ check(Q) = true
→ Code { syntax = Q }

The checker recursively verifies nonempty patterns, legal kinds, valid size operators, and well-formed recursive nodes.

Step 5 — unquote and evaluate ROOT/skip

Name("skip")        → true
Prune                → true
And                  → true
Or                    → true
print ROOT/skip
prunes(ROOT/skip)     → true
do not descend

hidden.c is never visited because the successful branch contains Prune.

Step 6 — evaluate remaining paths

ROOT/a.c       → Kind('f') = true  → print
ROOT/b.txt     → Kind('f') = true  → print
ROOT/sub/c.c   → Kind('f') = true  → print

Step 7 — final output

ROOT/a.c
ROOT/b.txt
ROOT/skip
ROOT/sub/c.c

4. Run it

make check-find-dsl

The test constructs a temporary filesystem tree, substitutes its root into the DSL source, invokes the separate compiler, checks the staged diagnostic, and compares the backend output. The local result is:

Find DSL compiler/backend: PASS

The implementation is an explicit total core, not complete GNU find compatibility. -exec and -delete remain outside this staged predicate language.
