Worked example · minimal ADT → AArch64

One program, four representations

This example shows where self-applicability helps: the compiler does not invent a separate constant-folding optimizer. It quotes the source term, applies the same normalizer to the quoted representation, reifies the result, and lowers only the canonical result to ARM64.

1. The source program

The language has inductive natural numbers and booleans, plus constructors for addition and conditional choice. This closed term deliberately contains two branches that can be discarded only after the condition is normalized:

(if
  (if false true false)
  (add (nat 17) (add (nat 5) (nat 3)))
  (add (nat 100) (add (nat 200) (nat 0))))

Its outer condition is itself an if. The true branch computes 25; the false branch computes 300. The inner condition chooses false, so the result is 300.

2. The typed ADT view

In the formal kernel, the relevant constructors are indexed by their result type:

Nat0 ::= Z0 | S0 Nat0
Bool0 ::= False0 | True0

Tm0 A ::= NatLit0 Nat0                  : Tm0 NatTy0
        | BoolLit0 Bool0                : Tm0 BoolTy0
        | Add0 (Tm0 NatTy0) (Tm0 NatTy0): Tm0 NatTy0
        | If0 (Tm0 BoolTy0) (Tm0 A) (Tm0 A): Tm0 A

An Add0 cannot receive a boolean, and both branches of If0 must have the same result type. The C++ front end mirrors these constructors dynamically and rejects malformed constructor applications when the evaluator cannot obtain the required indexed value.

3. The explicit staging projection

The compiler uses four projections. Quotation makes syntax inert; normalization consumes syntax data and produces syntax data; unquotation is the only boundary at which the compiler retrieves the normalized term for lowering.

ProjectionMeaningRole here
quote : Term → CodeTurn a term into syntax data.Prevents source syntax from executing implicitly.
normalize_code : Code → CodeNormalize the syntax carried by a code value.Performs branch selection and addition reduction.
normalize_code²Apply the same projection again.Checks the canonical/idempotent normal form.
unquote : Code → TermRecover staged syntax explicitly.Feeds only canonical syntax to the ARM64 emitter.
Term* self_apply_normalizer(Term* source) {
  Code once  = normalize_code(quote(source));
  Code twice = normalize_code(normalize_code(once));
  return unquote(twice);
}
What is self-applicable here? The normalizer is used as a first-class staged code transformation: its input and output are both code values, and its output can pass through the same normalizer again. The second pass is not a second hand-written optimizer; it is the same normalization projection.

4. Reduction trace

4.1 Normalize the condition

normalize (if false true false)
→ if (normalize false) (normalize true) (normalize false)
→ if false true false
→ false

The outer conditional therefore selects its else branch. The true branch is not lowered and does not need code-generation rules for its intermediate additions.

4.2 Normalize the selected branch

normalize (add (nat 100) (add (nat 200) (nat 0)))
→ add (nat 100) (nat 200)
→ nat 300

4.3 Canonicality check

normalize_code (quote (nat 300))
→ quote (nat 300)

normalize_code (normalize_code (quote source))
= normalize_code (quote (nat 300))
= quote (nat 300)

This is the practical payoff of the normalizer boundary: the backend sees one canonical constructor, not a family of source-shaped cases.

5. The generated ARM64

The result projection maps a natural value to its Linux process exit status. The compiler emits:

.text
.global _start
.type _start, %function
_start:
    mov x0, #300
    mov x8, #93
    svc #0
.size _start, .-_start

x0 carries the normalized result and syscall 93 is Linux AArch64 exit. If an AArch64 cross assembler is installed, the regression script assembles this text with aarch64-linux-gnu-as. On the host, the test still checks the exact ARM64 instruction contract.

6. What became simpler?

  • Branch pruning: no separate control-flow constant folder is needed for this pure language.
  • Arithmetic folding: the normalizer recursively reduces nested additions before code generation.
  • Canonical input to lowering: the emitter handles a literal value instead of every possible source tree.
  • Pass composition: future typed compiler passes can use the same Code → Code projection.
  • Regression criterion: direct normalization, staged normalization, and repeated staged normalization must agree.

This is intentionally a closed, pure example. Variables, functions, memory, effects, and recursion require additional typed projections and cannot be smuggled into this kernel merely by quoting them.

make check-minimal-arm64
