An eight-row, four-field ADT program

This is a complete two-stage example. Stage one is a user-written total checker: it validates every field tag in every row and constructs a typed array only after all eight rows pass. Stage two calculates a weighted total over the typed data.

The data shape

Each row has exactly four fields with four distinct roles:

FieldRaw constructorChecked typeRuntime meaning
amountRawNat4 nnatural numberbase quantity
enabledRawBool4 bbooleanwhether the row contributes
statusRawStatus4 Low4|Medium4|High4three-case ADTbonus score 1, 2, or 3
countRawCount4 nnatural countmultiplier

The array is not a variable-length list. Its constructor has eight positions:

Array8C row0 row1 row2 row3 row4 row5 row6 row7

Stage one: the type program

The raw input deliberately stores all fields in one tagged sum:

RawField4 =
    RawNat4 natural
  | RawBool4 boolean
  | RawStatus4 Status4
  | RawCount4 natural

RawRow4 = RawRow RawField4 RawField4 RawField4 RawField4

The checker is an ordinary total function, not a privileged type-checking oracle. Its pattern match accepts only the required four tags and constructs the typed record:

check_row4 (RawRow
  (RawNat4 amount)
  (RawBool4 enabled)
  (RawStatus4 status)
  (RawCount4 count))
= Some (Row4 amount enabled status count)

check_row4 any_other_shape = None

The array checker runs that type-stage program eight times. Its result type is option (Array8 Row4). Therefore a value of Array8 Row4 cannot be produced by the checker unless every row was accepted.

check_array8 raw =
  check row0 >>= fun row0' =>
  check row1 >>= fun row1' =>
  ...
  check row7 >>= fun row7' =>
  Some (Array8C row0' row1' ... row7')

Accepted

All eight rows have the four expected tags. Stage one returns a typed Array8 Row4.

Rejected

Even one wrong tag returns None. Stage two is not called.

Stage two: the calculation

After checking, the runtime stage assigns scores with one explicit formula:

row_score row =
  if row.enabled
  then row.amount * row.count + status_score row.status
  else 0

status_score Low    = 1
status_score Medium = 2
status_score High   = 3

calculate array = sum8 (map row_score array)

Result: stage one returns a typed eight-row array; stage two calculates Some 90. An incorrectly tagged eighth row returns None before calculation.

The complete two-stage pipeline

run_array8 raw =
  match check_array8 raw with
  | Some typed => Some (calculate4 typed)
  | None       => None

This is the central separation. The type stage is itself a finite ADT program with total semantics. It is not automatically sound with respect to an external type theory; its author is responsible for the checker specification. The runtime stage receives only the typed result of that program.

Reproduce and verify

coqc array8_four_field.v

The Coq examples prove by computation that the valid array produces 90 and the malformed array is rejected. The formal source is array8_four_field.v.

This is intentionally a fixed-size, total example. A variable-size array, mutation, pointers, or user recursion would require new stages and new proofs rather than being silently added to this kernel.
