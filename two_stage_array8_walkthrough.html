Eight rows through two explicit stages

This page gives the complete program, its grammar, its stage types, and its evaluation. The type stage is a total ADT program supplied by the user. Only after it has been normalized and has accepted all eight rows does the calculation stage receive a typed array.

1. The stage types

RawCode      = Code RawTerm
TypeCode     = Code TypeProgram
NormalizedTC = Normalized TypeProgram
Checked A    = TypedProgram A
Value A      = RuntimeValue A

The critical function types are:

normalizeType : TypeCode → NormalizedTC
check         : NormalizedTC → RawCode → Option (Σ A : Ty, Checked A)
run           : Checked A → Value A
Stage invariant: there is no function run : RawCode → Value A. Runtime execution requires a checked witness.

2. The grammars

Raw/runtime syntax

RawTerm ::=
    rawNat n
  | rawBool b
  | rawStatus Low | Medium | High
  | rawRow RawTerm RawTerm RawTerm RawTerm
  | rawArray8 RawTerm ... RawTerm

Type-stage syntax

TypeProgram ::=
    acceptNat
  | acceptBool
  | acceptStatus
  | checkRow TypeProgram⁴
  | checkArray8 TypeProgram
  | reject

The runtime type universe has four field types and two structural types:

Ty ::= Nat | Bool | Status | Row | Array8 Ty

3. The complete type-stage checker

The raw representation intentionally erases field types into one tagged ADT:

RawField ::=
    RawNat n
  | RawBool b
  | RawStatus s
  | RawCount n

RawRow = RawRow RawField RawField RawField RawField

The user-written checker restores the four field types:

checkRow (RawRow
  (RawNat amount)
  (RawBool enabled)
  (RawStatus status)
  (RawCount count))
  = Some (Row amount enabled status count)

checkRow _ = None

The eight-element checker sequences this operation exactly eight times:

checkArray8 (rawArray8 r0 r1 r2 r3 r4 r5 r6 r7) =
  checkRow r0 >>= fun v0 →
  checkRow r1 >>= fun v1 →
  checkRow r2 >>= fun v2 →
  checkRow r3 >>= fun v3 →
  checkRow r4 >>= fun v4 →
  checkRow r5 >>= fun v5 →
  checkRow r6 >>= fun v6 →
  checkRow r7 >>= fun v7 →
  Some (Array8 v0 v1 v2 v3 v4 v5 v6 v7)

Here >>= is the total option bind. A single wrong field tag changes the entire result to None.

5. Step one: normalize the type stage

Before checking data, the checker program itself is normalized:

normalizeType (quote checkArray8)
→ quote checkArray8

Because the checker is finite ADT data and its evaluator is structurally recursive, this stage terminates. Its normalized result is now the only checker supplied to the raw program.

6. Step two: check row zero

checkRow
  (rawRow (rawNat 10) (rawBool true)
          (rawStatus High) (rawCount 2))

→ Some (Row 10 true High 2)

The first field matches Nat, the second matches Bool, the third matches Status, and the fourth matches Count.

9. Final stage composition

run program =
  match checkArray8 (normalizeType typeProgram) program with
  | None => None
  | Some typedArray =>
      Some (sum8 (map rowScore typedArray))

run program
→ Some 90
Final result: the type stage completely normalizes and checks the eight-row data before stage two calculates Some 90.

10. Rejection trace

If row seven ends with RawBool true instead of RawCount 2:

checkRow (rawRow (rawNat 5) (rawBool true)
                  (rawStatus Low) (rawBool true))
→ None

checkArray8 badProgram
→ None

run badProgram
→ None

The calculation stage is never entered.

Source and verification

coqc array8_four_field.v

The formal source proves by computation that the valid program returns Some 90 and the malformed program returns None. The repository source is array8_four_field.v.

This design proves termination and stage separation. It does not automatically prove that an arbitrary user-authored checker matches an external intended type theory; that remains a separate checker-soundness theorem.
